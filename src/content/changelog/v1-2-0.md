### Added

- **Configurable brand** — `APP_NAME`, `APP_URL`, `APP_GITHUB_URL` and `APP_LEGAL_NAME` are build-time values (`src/lib/brand.ts`) that drive UI titles, SEO tags, structured data, the PayPal `brand_name`, the email sender name and the web manifest. `APP_NAME` alone renames the whole site.
- **`{app}` interpolation** — `translate()` resolves a `{app}` placeholder from `APP_NAME` globally, so the i18n dictionaries no longer carry the product name and stay conflict-free when syncing upstream.
- **Parameterised deploy naming** — `CF_WORKER_NAME` sets the worker name prefix in CI, and the `db:*` scripts read the real D1 name from `wrangler.jsonc` via `scripts/db-name.mjs` instead of hard-coding five copies of it.

### Changed

- `common.appName` and the brand copy in `en.ts` / `zh.ts` are now `'{app}'` placeholders. Set `APP_NAME` rather than editing the dictionaries.
- `EMAIL_FROM` blank now falls back to `<APP_NAME> <onboarding@resend.dev>`.
- The web manifest is served by a route (`/manifest.webmanifest`) instead of `public/manifest.json`, so its name can follow `APP_NAME`.
- Repository links (header, footer, docs nav, `git clone` hints) render nothing when `APP_GITHUB_URL` is falsy, instead of producing a dead `href=""`.

### Notes

- `AGENTS.md` gained a "本地约定" section for downstream-only notes, and upstream keeps its own content untouched — forks are expected to put their rules in `AGENTS.local.md`.
- Documentation (`src/content/docs/**`) still names the template: docs are the template's own subject matter and are meant to be rewritten downstream.
