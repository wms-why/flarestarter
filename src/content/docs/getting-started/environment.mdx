在根目录下有一个 `.dev.vars.example` 文件。当你进行本地开发时，需要将其复制并重命名为 `.dev.vars`。

<Callout type="info">
在 Cloudflare Workers 环境下，生产环境的密钥不是写在文件里的，而是需要使用 `wrangler secret put <KEY>` 命令设置到 Cloudflare 面板中。
</Callout>

## 核心配置

<TypeTable
  type={{
    BASE_URL: {
      description: '应用的基础访问地址',
      type: 'string',
      default: 'http://localhost:3000',
    },
    BETTER_AUTH_SECRET: {
      description: 'Better Auth 用于加密 Session 和 Token 的密钥。',
      type: 'string',
    },
  }}
/>

## 构建期变量(Vite,不是 Cloudflare env)

有一类变量在 **`vite build` 的时候**就被读出来、**内联进产物**,而不是等 worker 运行时才注入。
目前是品牌配置和 GA:

<Callout type="info">
这类变量请写在 `.env`(本地,参考仓库里的 `.env.example`)或 CI 的环境变量里,**不要**写进
`.dev.vars` / `wrangler secret`——Cloudflare 的 var 要等 worker 跑起来才存在,那时产物早已定型,
「没配就不集成」就落空了。
</Callout>

<TypeTable
  type={{
    GA_MEASUREMENT_ID: {
      description: 'Google Analytics 4 衡量 ID(形如 G-XXXXXXXXXX)。留空 = 打包不集成:产物里没有 GA 代码,浏览器不会向 Google 发请求,生产 CSP 也不放行 Google 的域名。详见 [可观测性](/docs/platform/observability)。',
      type: 'string',
    },
  }}
/>

### 品牌

**改品牌只需要改这 4 个变量**,不必碰任何组件——所有 UI 文案、页面标题、SEO 标签、
结构化数据、PayPal `brand_name`、邮件发件人显示名和 web manifest 都从
`src/lib/brand.ts` 读。详见 [品牌与元数据](/docs/customization/branding)。

<TypeTable
  type={{
    APP_NAME: {
      description: '产品名:UI 标题、SEO、邮件发件人显示名、PayPal `brand_name`、结构化数据、web manifest。i18n 字典里的 `{app}` 占位符全局解析成这个值。留空 = `FlareStarter`。',
      type: 'string',
      default: 'FlareStarter',
    },
    APP_URL: {
      description: '站点根 URL:canonical / `og:url` 的 origin 优先取它,还是模板的 `*.example.com` 时回落到 `BETTER_AUTH_URL`。认证跳转仍由 `BETTER_AUTH_URL` 决定。留空 = `https://flarestarter.example.com`。',
      type: 'string',
      default: 'https://flarestarter.example.com',
    },
    APP_GITHUB_URL: {
      description: '页头/页脚/docs 导航里的仓库链接(以及 `git clone` 提示)。留空 = 模板仓库;设成 `-` = **不展示**仓库链接(所有渲染处都判空,不会留下死链)。',
      type: 'string',
      default: 'https://github.com/flarestarter/flarestarter',
    },
    APP_LEGAL_NAME: {
      description: '法务页与版权行用的法定主体名。留空 = 跟随 `APP_NAME`。',
      type: 'string',
      default: '同 APP_NAME',
    },
  }}
/>

<Callout type="warn">
`en.ts` / `zh.ts` 里的 `common.appName` 值是占位符 `'{app}'`,**不要**把它改回字面量。
`translate()` 会把 `{app}` 解析成 `APP_NAME`(见 `src/features/i18n/locale.ts` 的
`GLOBAL_PARAMS`),这样下游改名时两个字典都不用动,同步上游也不会冲突。
</Callout>

## 数据库 (D1)
无需在此处配置数据库账号密码。Cloudflare D1 使用绑定的 Database ID，详情请见 [部署到 Cloudflare](/docs/getting-started/deploy)。

## 邮件 (Resend / Flowmails)
用于发送登录验证码或营销邮件。`EMAIL_PROVIDER` 选服务商(默认 `resend`),两个服务商的 key 互不兜底 —— 选了 flowmails 却只配了 Resend key,邮件会降级为控制台捕获,而不是换个服务商真发。详见 [邮件](/docs/features/email)。
<TypeTable
  type={{
    EMAIL_PROVIDER: {
      description: '邮件服务商:resend(默认)或 flowmails。写错的值会让启动直接报错,不会悄悄回落。',
      type: 'string',
      default: 'resend',
    },
    RESEND_API_KEY: {
      description: '从 Resend Dashboard 获取的 API 密钥,仅在 EMAIL_PROVIDER=resend 时读取',
      type: 'string',
    },
    EMAIL_FLOWMAILS_APIKEY: {
      description: 'Flowmails 控制台签发的 API 密钥(fm_…),仅在 EMAIL_PROVIDER=flowmails 时读取。key 绑定一个域名,EMAIL_FROM 必须落在该域名上,否则发信返回 422 from_domain_mismatch。',
      type: 'string',
    },
    EMAIL_FROM: {
      description: '发件人邮箱,例如 noreply@yourdomain.com;也可写成 `FlareStarter <noreply@yourdomain.com>`,显示名会单独传给 Flowmails',
      type: 'string',
    },
    AUTH_EMAIL_VERIFY: {
      description: '注册时是否强制邮箱验证。留空等同 true:用户须点验证邮件才能进后台。设为 false 则注册完直接进后台(不建议生产环境这么做)。留空/true 时仍需配置所选服务商的 API 密钥,否则链接发不出去,验证会自动降级为关闭。',
      type: 'string',
      default: 'true',
    },
  }}
/>
